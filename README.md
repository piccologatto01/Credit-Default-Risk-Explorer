# Credit scoring: прогноз дефолта по кредитной заявке

Учебный end-to-end проект по классическому кредитному скорингу для данных соревнования [Tinkoff Credit Systems на Kaggle](https://www.kaggle.com/c/tinkoff-credit-systems). Пайплайн обучает интерпретируемую логистическую регрессию, учитывает дисбаланс классов и строит интерактивный риск-дашборд.

## Что показывает проект

- качество ранжирования: **ROC-AUC** и **Gini = 2 × AUC − 1**;
- качество редкого положительного класса: **Average Precision** вместо accuracy;
- бизнес-точку отсечения: максимальную точность (precision) при заданной минимальной полноте обнаружения дефолтов (recall);
- долю заявок ниже порога риска — учебную интерпретацию approval rate;
- концентрацию дефолтов по децилям риска;
- признаки, сильнее всего связанные с ростом или снижением предсказанного риска;
- пропуски и высококардинальные/константные признаки, исключённые из модели.

Accuracy намеренно не является главной метрикой: при редком дефолте модель «все клиенты хорошие» может иметь высокую accuracy и нулевую практическую ценность.

## Интерактивный дашборд

Фронтенд написан на чистых **HTML, CSS и JavaScript**, без Streamlit и Plotly. Все графики строятся в SVG с помощью **D3.js v7**:

- ROC-кривая и ROC-AUC;
- кривая точности–полноты (Precision–Recall) и Average Precision;
- дефолтность и накопленная доля найденных дефолтов по децилям риска;
- факторы модели с направлением связи с прогнозным риском;
- распределение прогнозной вероятности для двух классов и рабочий порог.

Интерфейс включает состояния загрузки и ошибки, поддержку `prefers-reduced-motion`, клавиатурный доступ к прокручиваемым графикам и мобильные подсказки горизонтальной прокрутки. У каждого графика есть текстовое описание, раскрываемая таблица и ссылка на полный CSV — данные остаются доступны без наведения мышью и не зависят только от цвета.

> D3.js и веб-шрифты загружаются через CDN, поэтому при первом открытии дашборда нужен доступ в интернет.

## Данные Kaggle

Скачайте файлы соревнования после входа в Kaggle и принятия его правил, затем положите CSV в `data/raw`. Пайплайн распознаёт распространённые имена:

```text
train.csv / credit_train.csv / application_train.csv
test.csv  / credit_test.csv  / application_test.csv
```

Если Kaggle CLI установлен и авторизован:

```bash
kaggle competitions download -c tinkoff-credit-systems -p data/raw
unzip data/raw/tinkoff-credit-systems.zip -d data/raw
```

Target определяется по распространённым именам (`target`, `default`, `loan_default`, `is_default`, `label`), ID — по `id`, `application_id`, `client_id` и аналогам. Для нестандартной схемы задайте их явно:

```bash
python -m src.risk_analytics.pipeline \
  --data-dir data/raw \
  --output-dir data/processed \
  --target-column TARGET \
  --id-column APPLICATION_ID
```

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

make demo       # генерация синтетических заявок + обучение
make dashboard  # http://127.0.0.1:8501
make test
```

После запуска откройте [http://127.0.0.1:8501](http://127.0.0.1:8501). Локальный сервер отдаёт только файлы фронтенда и результаты из `data/processed`.

Для реальных данных:

```bash
make analyze
make dashboard
```

Порог можно настроить под риск-аппетит. Например, требовать обнаружить не менее 80% дефолтов:

```bash
python -m src.risk_analytics.pipeline \
  --data-dir data/raw \
  --output-dir data/processed \
  --minimum-recall 0.80
```

## Модель и дисбаланс

Используется логистическая регрессия с `class_weight="balanced"`. Числовые признаки заполняются медианой и стандартизируются, категориальные — заполняются модой и one-hot кодируются. Разбиение train/validation стратифицированное, поэтому доля дефолтов сохраняется в обеих частях.

Это прозрачный baseline, близкий по логике к традиционному скорингу. Коэффициенты агрегируются до исходных признаков и показывают направление связи с дефолтом. Они **не являются доказательством причинности** и перед продуктивным использованием требуют проверки стабильности, утечек, справедливости и регуляторных ограничений.

|---|---|
| `summary.json` | ключевые метрики и выбранный порог |

| `risk_deciles.csv` | дефолтность и накопленный capture по децилям |
| `score_distribution.csv` | распределение скорингов по классам |
| `feature_importance.csv` | агрегированные коэффициенты и направление риска |
| `missingness.csv` | качество входных признаков |
| `credit_scoring_model.joblib` | обученный sklearn pipeline |
| `submission.csv` | прогноз для test, если test-файл найден |
